# 编辑已有文字

用户已有自己要修改的成稿，要求润色、去AI味、重写、审阅或对比时读取。对方说的话是聊天输入、用户尚未写回复时，使用[聊天代写](chat.md)，不要把对方的话当成要润色的回复。

## 先看这是什么体裁

先通读全文，理解作者想表达的事、各段关系和已有口气，再结合体裁选择改法。体裁帮助判断表达的作用，不把其中每个词句都设成不可改；未提供用途时不必先让用户选模式。

| 语境 | 重点理解与核对 |
|---|---|
| 平台文案、评论 | emoji、口语、吐槽及重复可能承担情绪和节奏。修顺生硬句子时保住作者态度；辨认标题、正文、页面信息和误粘贴，不因像平台成分就全留或全删。 |
| 操作说明、技术介绍 | 读者能否辨认对象、条件、步骤和结果；术语、界面名及参数是否准确。复杂描述可简化，不能用意思接近的词模糊分类或扩大范围。 |
| 简历、面试自我介绍 | 经历与岗位要求的对应关系是否清楚，内容有无重复。口述还要简洁、不绕口、易记，让说的人能讲完、听的人记得住重点，不强套固定模板。 |
| 通知、公文、会议纪要 | 事项、人员、时间、职责、条件和要求力度是否明确。遵守用户提供的格式、规范和固定口径；没有明确限制时可有依据地简称、顺句和整理结构。 |
| 客服指引、回复 | 辨认各部分给谁看、要交代什么。内部操作要准确可执行，客户回复要容易理解状态、行动和更新时间；不强制制造两套文风，未知状态及待填占位符不编填。 |

原稿有明确格式要求时优先遵守，在允许范围内适配内容。已有有效层级可沿用；碰巧粘成一段或编号混乱，不等于要求保持原状。公文全称是否简写、虚词是否删减、句式是否调整，看指代、发文要求和实际含义，不按单个词判错。

称呼或人称前后不一致时，先看是否同一说话者、同一对象，或属于引用与角色切换。确认无意不一致就修正；按上下文和用户意图选“你”或“您”，不把统一称呼捆绑为整篇口语化。主语已清楚时可以省略，有助于承接和节奏时可以保留。

## 改到哪里，由本次要求决定

润色可以换词、换句式、调整讲述顺序和组织方式，让原意更好理解；保住事实、判断、信息范围及明确要求的结构。摘要、扩写、换立场和删去独立信息需要相应要求。只要求校对、排版或建议，就停在该范围，不借机重写或改文件。

按语义关系决定是否分段、加标题、列条目或合并，格式服务于阅读，不要求统一。不要只加整齐的小标题，却让原来别扭的句子留着；也不要为显得改得多而重排本来清楚的文字。

遇到内容错乱或残缺，先理解整段，再选择修编号、调顺序或理层级；不要仅按数字机械排序或凑齐条目。补足省略、合并重复、剥离页面残片要有上下文依据，整理后重新核对关系。仍有多种解释且会影响事实、责任、操作对象或执行时，再问一句或指出具体缺口；可确定的部分先改顺，不为完整编造未知内容。

## 先记住不能改掉的意思

- 人物、对象、数字、单位、时间、范围、条件、否定、比较、因果、优先级、操作先后及同时发生的关系。
- 谁作出的主张，是观察、推测、计划还是已完成；“可能、据称、仅、尚未确认”承载的强度。
- 作者的批评、犹豫、评价、感受和正式程度；精简不把有用判断磨成中性简介。
- 谁交付什么、何时交付、在什么条件下、是可以还是保证；这些可能藏在客套和预告里。

核对谁在做、对谁做、谁受益，以及原文表达的是事实、能力判断、意愿、计划、正在进行还是已完成。同一对象可用不含混的简称、代词或省略；称呼可按上下文与用户意图统一。没有相应要求或依据时，不把团队改成个人，不把可能做到改成想做或已经在做。

务必、必须、不得、严禁、仅限、截止、需经审批等可能承载强调、义务、禁止、范围或前置条件。结合句子核对这些含义及要求分寸，不能无理由改成建议、尽量或省掉条件；等价改写可以，不能仅按是否保留原词判定。“请务必”精简为“务必”可成立；“必须”变“建议”改变强制程度。指代明确时“参会”可写“参加”；“我们”可换成已明确指定的团队名称，但不能变成“我”。

抽象也可能有内容。缺数据不代表作者没表达判断；不能为了具体补措施、性能、价格或经历，也不能把作者对结果的评价当作数据的重复。用户要求去掉宣传或夸张时可降调，仍保住可核查功能、排名、数字、承诺和原有立场。

排除一种解释不等于肯定相反事实；未确认网络导致失败，不等于网络正常。相关和先后不能自动变成因果，“参与”不能变成“负责”。

## 保护片段与来源

作为依据的原话、文献、界面措辞、标准定义，以及代码、命令、路径、链接、表格数据和明确要求原样保留的部分，除非本次点名修改，否则保留。外层引号只是圈出待改稿件时，不因此把整份稿件冻结；判断引号内容的用途。

引用与其支持的陈述一起移动，不把标识挂到更广的结论之后。缺来源的“研究称”不能只删归属，让论断变成无条件事实；疑点放正文外简短说明，不猜来源、不静默改立场。润色不等于已核实事实。

把“业内公认”“据专家认为”改成“有专家认为”“不少专家指出”，换的只是归属的说法，来源仍然没有，这类替换不算处理。用户只要成稿时，保留作者原本的转述方式；确实要提示缺出处，放在正文外一行说清，不替作者补人名、机构或研究名。

## 再处理影响阅读的表达

默认改成更好懂的那一版，而不是更短的那一版。同样清楚时选短的；短和清楚冲突时选清楚。

看具体作用：无信息的开场与结尾、完整的语义重复、没有实义的强调、主干被长定语压住、每段反复得出同一结论，才值得改。能指出阅读问题再动手，不凭一个词、列表项数或标点判错。

**先看哪句读着费劲。** 缺词、搭配生硬、指代含混、主干被修饰压住时，可补词、换说法、拆合句子。允许自然的口语省略，不把简写都当语病。复杂经历或情绪化叙述先理清各方动作与对话，再按容易理解的顺序讲；改变讲述顺序时保住实际时序、因果和责任归属。

重复要看作用：拖沓、误粘贴和无信息复述可精简；强调、情绪、节奏和消歧可能需要重复。标点、连接词和段落帮助读者辨认关系，不凭句号多少、同词次数、是否工整或有无分号判错。专业名词可采用已确认等价的规范表述或简称，复杂解释可以简化；不能仅凭同音或日常近义就替换术语，丢掉分类、定义、适用范围或操作含义。

**压短不等于压重。** 删字时不能顺手把话说重：“将讨论A、B、C”不是“A、B、C是主要问题”，“打算说明几件事”不是“问题卡在这几处”。并列的预告收成一句时，保留它原本的陈述强度；作者只是在列提纲，就别替他下结论。同样，删除限定词、把“可能”写成“是”、把“参与”写成“负责”，都属于压短越界。

这条也包括换一种说法提升强度：“绕不开这三件事”“关键在于三点”“这三件事决定成败”，都在替作者宣布重要性。作者只是在列要讲的题目，就照实说“文章讲这三件事”。

**改完发现原文其实没说什么，要说出来。** 去掉包装后只剩一句空话时，不能用更顺的句子把空洞填平，也不要为了显得有内容补例子和推论。可以照原意交付，并在正文外说明这段目前只有这个意思、缺具体对象或依据。把空话改得好看，比原来更难发现。

**精简不是每句都要切一刀。** 一句已经清楚的话，改成更短反而变别扭，就不动它。删到该留的都留住以后，剩下的工夫花在把绕的拉直上，而不是继续砍字数。

稿子成串出现抽象评价、时代背景开场、拔高收尾，或整篇按定义、分层、推论一路铺开时，按[话术、组织逻辑与词汇检查](doc-tics.md)处理。命中其中某个词本身不算问题，看的是这段话说清了自己要说的没有。

让已知动作和对象承担主干，可以补足上下文已明确的指代，不补未知的执行者。同一对象保持可追踪的指称，允许必要重复和有依据的简称。原有的关心、玩笑、反问、态度或转场有作用时保留；不要为了自然注入这些内容，也不要为了克制清掉它们。

## 短稿里的词也要看作用

短稿篇幅不够展开整份清单，但中段的词仍然会露出同类问题。一处稿子里出现两三组下列信号时，就地处理，不必先读长文检查表：

- **空动作**：赋能、助力、驱动、构建——没有交代谁做了什么，材料里有动作就写动作。
- **大概念**：生态、闭环、抓手、底层逻辑——是不是给普通事情换了个更重的名字。
- **扩音词**：最值得警惕、结论很明确、显著、全面——只提高音量，没有给出对象或依据。
- **假口语**：讲真、说白了、盘一盘——结合作者口气看转场是否有用，保留自然习惯，精简无作用的装饰，不凭词本身判错。
- **无源权威**：业内公认、专家认为、研究表明——谁说的、依据在哪；不能只删归属把说法变成事实，也不能把“据专家认为”换成“有专家认为”了事。
- **同义轮换**：工具、平台、方案来回换名，或用提升、增强、优化轮流说同一件事。

单个词在引用、术语定义和作者原有习惯里不必改。“业内公认”若是作者正在批评的说法，“赋能”若是被引用的口号，就要留住。判断的是这个词在本稿里有没有干活，不是它的出现次数。

短稿里这部分问题集中在两三处时，也可以只按上面几条改完交付，不必为了核对全部词群去读长文清单。全篇组织或句式也有问题时，再按[话术、组织逻辑与词汇检查](doc-tics.md)展开。

## 短评的结尾也要检查

短评常在最后把使用意见写成“先解决X，才谈得上Y”“真正的价值还要看……”这类产品总结。先找作者实际在批评什么、建议改什么，保留判断和条件，再把话说回那个具体问题。不要只将“生产力”换成“价值”或“体验”，也不要为了结尾完整再补一条路线图、展望或金句。用户已有的建议和版本先后仍要保留。

能用已知的限制及其直接影响说清，就不另起一个抽象结论。材料只说并发或配额受限，不能补出排队时长、每天次数、实际故障或不存在的使用经历；也别靠“太顶了”“用不爽”等口语装饰代替原来的意思。

这些句式不是禁用项。真实的操作前提、必要条件和有具体含义的术语照常保留；仅有表达问题时局部改，不把整段压成一句含糊评价。

## 改完逐处对照

先以读者身份通读整篇，看主线、段落关系和句子是否顺畅，有没有仍需猜测的对象或动作。原有难读、粘连、搭配生硬或指代不清的地方是否真正改善，不只是换了格式或断了句。再对照原稿的重点、事实、术语分类、条件、人物关系、引用归属和语气分寸，检查是否遗漏、误接或扩大。

按整段含义核对，不以某个字是否保留判定保真。换词、简称或省略主语后仍明确表达原意，可以保留；有作用的信息、态度或强调丢了就放回。有疑问时回到上下文判断，必要时修正或确认。原句已经清楚、替换没有改善时就沿用，不为完成修改量反复打磨；但原文确有难读处时，不能以“保留作者口气”为由跳过。

默认交完整可用稿。审阅时引用具体片段，说清问题及修改方向，不凑条数；用户要前后对比时展示实际对应变化，不输出自评分。默认不附复核报告；用户要求说明改了什么时再展示，且说明必须与最终稿一致，不能以自述代替正文。

## 表达审阅与自然度复核

用户说“像AI”“帮我检测”时，先分清是在要求审阅还是改稿。审阅只报告能定位的问题：这句话重复了什么、哪个判断缺少承接、哪处语气与体裁或作者样本不合；不根据整齐、正式、流畅或某个词猜作者来源，也不强凑问题和百分比。

改稿时把这些判断用于内部检查：改动前知道要解决哪处问题，改完确认问题确实减少，同时没有丢掉独立信息、加重判断或抹平作者口气。若改后更含糊、只是换一套说法或破坏体裁，撤回那处改动。没有明确改善就保留原文；默认不展示检查过程。

自然度以目标读者能否读懂、这位作者是否会这样表达为准。不为显得像真人补错别字、感官细节或经历，也不追求固定句长、词频、困惑度或外部检测分数。检测器提示只可作为待核对的线索，不能替代上述判断。

## 用例

以下为自拟编辑示例，说明语义边界，不是固定答案。

**简化表达，不补结果。** “完成了对配置的检查”可改为“检查了配置”，不能补成“确认配置正常”。

**保住不确定性。** “维护者称补丁计划于周四发布。故障可能与缓存有关，原因尚未确认。”不能写成“周四将修复缓存故障”。

**保住作者反对的依据。** “我不建议团队现在换工具A。它有离线模式，但导出仍在测试，目前只能导出PDF；我们每周还要交可编辑文档。”可以理顺句子，不能只剩“工具A有一些限制”。

**客套中有承诺。** “如果你还需要，我可以周三把核对表发给你；财务确认前，只供内部讨论。希望这些能帮上忙。”可删最后一句，意愿条件、交付者、时间、“可以”和流转限制都留。

**引用不替作者作判断。** “8个样本中有5个成功导出。[记录1] 我认为现在不适合全组使用。”引用仍绑定样本数据，不移到使用建议之后，不外推成产品的一般成功率。

**明确的范围只做范围内的事。** 只把“首先检查文件格式。其次进行数据校验。”各分一段，就保留原字句。原稿“我试了两次，第二次还是没导出成功。明天换个文件再试。”已清楚，也可以原样交付。

**聊天成稿也有原意。** 润色“这两天先歇歇吧，周末我去看你”，不能因为聊天规则提醒不擅自邀约，就删掉用户已经写出的约定。

**评论落回具体限制。** “每天只能导出两次，先解决次数限制，才谈得上服务专业用户。”可以试改为“每天只能导出两次，给专业用户用还是少了，次数上限得提高。”保留次数、评价和改进建议，不另补“付费版无限导出”等功能。这是自拟编辑方向，不是用户认可的范文。

**真实前提不动。** “先确认备份成功，再删除原文件。”是必要的操作顺序，不因有“先……再……”而改掉。
