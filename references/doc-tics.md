# 话术、组织逻辑与词汇检查

写作或编辑的稿子出现成串抽象评价、模板化组织或拔高收尾时读取。短评的局部处理先用[编辑规则](editing.md#短评的结尾也要检查)；单个词出现在引用、术语或作者习惯里不必读，同一段里两三组词群反复出现时才需要核对词汇表。

这些是候选编辑信号，不鉴定作者。先判断这段话在做什么，再看具体问题处于篇章、句式还是用词层；只处理影响当前稿子的部分，不要求每次扫描全表。改动幅度与信息保护仍服从[编辑规则](editing.md)。

## 常见话术与句式

| 写法 | 值得检查的情况 | 处理方向 |
|---|---|---|
| 时代与趋势开场 | 背景能套在任何同题文章上，没有本篇信息 | 从已有事件、对象或判断进入；有用背景保留 |
| 分析过程预告 | 只是在说接下来讲什么、刚才讲完什么 | 直接写下一项内容；长文导航和教程导读有用时保留 |
| 假揭示、强行对照 | “看起来是X，真正的问题是Y”没有真实差别，或凭空设一个反面再推翻 | 直接表达原意；确有对比、纠错或范围排除时保留，不因句式常见而改掉 |
| 极值与扩音提示 | “最值得警惕的”“结论很明确”等只提高音量 | 直接给判断和依据；作者确有强烈态度时保留强度 |
| 产品资格式收尾 | 由一个使用限制跳成“先解决X，才谈得上真正的Y” | 回到已有的限制、影响和建议，保留条件及版本先后，不另造产品路线图 |
| 无内容的平衡与转折 | 先说仍有挑战，再固定补一句前景乐观，没有真实权衡 | 保留实际的优点、缺点和态度；不强凑两面或统一收成积极结论 |
| 提示语加冒号 | 只是宣布下面是重点、答案或结论 | 能直接说就直接说；定义、原话、列表和必要解释不因有冒号而改 |
| 正文混入助手口吻 | 成稿后还在解释怎么用、主动邀约继续服务 | 去掉无任务作用的协作残留；不能一并删掉作者已有的交付承诺 |

形式本身不是错误。“先确认备份成功，再删除原文件”有必要的先后关系；“只有管理员批准后才能导出”有必要的权限条件。不能为了避开关联词，把这类信息改没。

“会议不是周四，而是周五”在纠正时间，可以保留。起草时材料只说周末想休息，不能自行写成“休息不是偷懒，而是找回生活的掌控感”，补出材料没有的反面判断和心理意义。作者本来写出的感悟仍按原意和本次要求处理。

## 常见的组织与推论问题

- **先定义，再分层，再讲边界，最后给行动。** 每一项都有内容时可以成立；只有一个小判断却被展开成整套讲解时，删去不服务读者的问题。
- **段段都是观点、解释、升华。** 看每段增加了什么，合并同义复述；只换连接词不能消除重复。真实递进和有作用的情绪强调保留，不为改变外观强制打散段落或改变长度。
- **过渡很多，信息不动。** “进一步看”“换个角度”“这又说明”后仍在重复前句，删多余台阶。真实推导、因果和转折仍需清楚。
- **人为制造误解再推翻。** 没有材料表明读者以为X，就不替读者安排这个误解。原文确有事实纠错或范围排除，则保住区分。
- **把先后写成因果，把样本写成普遍结论。** 这涉及命题，不是简单去套话。编辑时保住作者原意，必要时在正文外指出疑点，不悄悄替作者改立场。
- **处处补边界和免责声明。** 同一保留意见反复出现可以合并；证据等级、适用范围、风险与未知状态不是赘语。
- **每段封口，全文再总结一次。** 没有新判断或行动时停在最后一句有信息的话。正式结论、摘要和用户要求的下一步照常提供。

不要把这些提醒反着执行：不为自然故意跳跃、不为变化加入反例和经历、不为避免列表把操作步骤写散。

## 难懂：绕出来的深度

文字读着费劲，不等于内容更有分量。检查主干、指代、信息关系和术语是否适合读者，不据此推断作者是否想清楚或有意卖弄。

**读起来要往回读的地方，就是问题所在。** 一句话读完不知道主语是谁、动作落在哪个对象上、前后半句靠什么连起来，这些不是读者水平不够。

- **一句里套三层。** 定语套定语、“在……的情况下”“对于……而言”层层包裹，主干被推到句尾。把主干提出来先说，修饰放到后面或另起一句。
- **抽象词接抽象词。** “通过构建体系化能力实现价值闭环”没有交代具体对象和动作。材料已有这些信息时可写清；材料不足时保留准确概括，必要时指出缺少的具体信息，不编细节，也不据此评价作者的思考能力。
- **术语堆砌。** 一个概念用两三个近义术语轮着说，或本来有常用说法不用。术语有确定含义时照常保留，不能为了白话把专业概念改错；删的是那些不承担信息、只为增加分量的词。
- **用复杂换分量。** 简单的判断被说成“从多个维度来看”“在更深层次上”，其实只有一个意思。把那个意思直接说出来。
- **绕开结论。** 一段话读了不知道作者到底主张什么，只看到各种条件和可能性。作者有判断就写清楚；确实没有结论，就承认还没定，不要用一堆限定语掩盖。
- **把简单事说成流程。** 一件两句话能交代的事，写成五个步骤和三个注意点，读者反而抓不住重点。

调完再读一遍，判断标准只有一个：比原来好懂了吗。变短但更难懂，就是改坏了。

## 词汇与语气：看它承担什么信息

| 词群与例子 | 检查什么 | 不能误删什么 |
|---|---|---|
| 抽象动作：赋能、驱动、助力、构建、实现 | 谁做了什么是否被空动词盖住；材料有动作就写动作 | 真实的目标、作用与作者判断；不能因不够具体而补造功能 |
| 概念包装：生态、闭环、抓手、底层逻辑 | 是否只是给普通事情换一个更重的名字 | 技术定义、行业术语、正在被讨论的措辞 |
| 效果与程度：显著、深刻、全面、革命性 | 有没有具体对象、依据或作者明确态度 | 数值对应的程度、已经表达的评价，不一律降调 |
| 总括评价：生产力、价值、体验、潜力 | 指向具体指标或判断，还是给结尾凑一个大词 | 概念本身有清楚含义时保留；不能只换成另一个抽象词 |
| 讲解与假口语：拆一拆、盘一盘、讲真、说白了 | 是否只是在演示亲切或宣布开始分析 | 结合作者口气判断，保留有作用的习惯与真实转场；无作用的赘语可精简，不因原文已有就冻结，也不强加聊天腔 |
| 路标与权威：值得注意、专家认为、研究表明 | 提示语是否多余，归属有没有来源 | 来源归属不能只删掉；缺出处时不把主张改成裸事实 |
| 限定与安全垫：可能、通常、似乎、某种程度上 | 是否多次表达同一种犹豫 | 时间、范围、否定、证据强度与真正未知的情况 |
| 同义轮换：工具、平台、方案反复换名 | 同一对象是否越换越难追踪，是否换词重复结论 | 术语一致、必要点名和消歧重复 |

不统计“每千字能出现几个”，也不把一个词当成AI证据。判断标准是改完有没有更好懂：同样清楚时选短的，短和清楚冲突时选清楚。

## 按文体落到改动

工具介绍讲用途和限制；短评保住作者的实际意见；教程保住步骤、前提和失败条件；通知保住时间、对象和要求。个人文章的犹豫、反问、批评和未展开的想法也可能是作者声音，不能统一抛光成说明书。

最后对照原稿或材料：删掉的是没有作用的包装，还是连同事实、评价、条件、来源也删了？改完若只是把“价值”换成“体验”、把“赋能”换成“加持”、把书面套话换成“讲真”，仍需回到具体意思。不要添排队时长、界面操作、测试经历等没有来源的细节来换取所谓具体。
